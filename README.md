# Blossom Lingo

一个本地优先的 Chrome/Edge 扩展：翻译你当前有权访问的 LeetCode Explore 页面，并在原文下方显示译文。正文只发送到本机 Ollama，不经过第三方服务器。

`1.3.4` 支持导出没有讲义正文、仅含练习题的课程。Markdown/HTML 会生成分章练习题链接集，保留题目名称和 LeetCode 原始地址；封面与弹窗显示讲义数和练习题数，不再因“0 篇讲义”而静默失败。

`1.3.3` 将 LeetCode 目录元数据中的 `Coding Question` 直接归类为在线练习题，在目录扫描完成时批量保存原始链接并计入“练习题”，不再逐页等待后以未知类型跳过。“仅重试失败项”也会修复旧任务中因此被跳过的条目。

`1.3.2` 在课程进度页为当前任务日志和历史任务日志增加一键复制按钮，复制带本地时间戳的完整纯文本日志，并显示复制结果。

`1.3.1` 翻译每篇文章的标题，并将中文标题用于单篇及整课 Markdown/HTML 的主标题、目录、篇章导航和下载文件名；英文原标题作为副标题保留，方便核对。

`1.3.0` 补全 DSA 课程内容：识别并翻译选择题题干与文本选项；适配 LeetCode CSS Modules 生成的 `question-desc__*` 题干容器，并从单选项组的上一层题目容器识别没有稳定 class 的题干，同时排除 “Multiple Choice Question” 标签。代码块不参与翻译，但按原语言和原始内容写入 Markdown fenced code block 与 HTML `<pre><code>`；图片、视频和 iframe 以逐项资源链接写入两种归档。折叠问答进一步兼容 Bootstrap、自定义 question title、accordion 和 spoiler 控件。

`1.2.0` 支持课程正文中的折叠问答：翻译前会展开原生 `<details>` 以及通过 `aria-expanded`/`aria-controls` 标记的折叠面板，同时翻译问题标题和展开后的答案。Markdown 与 HTML 归档会把这些内容重新组织为可展开的双语 `<details>` 问答块；打印时默认保持展开，避免答案遗漏。

`0.9.0` 起，通用模型通过 Ollama JSON Schema 结构化输出译文，并检查条目 ID 与完整性；若小模型仍生成损坏的 JSON，会自动降级为逐段纯文本翻译，不再让整篇文章因一个逗号或引号失败。

`1.0.0` 将没有课程讲义正文的题目条目标记为“练习题”并保留原始链接，不再用含义模糊的“页面不含可归档正文”计为跳过。课程目录、处理状态和练习链接会随归档一起保存。合并 Markdown/HTML 提供分章编号、可点击目录、文章回到目录链接、封面、状态图例和适合 A4/PDF 的响应式排版。

`1.0.1` 修复测验页的加载竞态：只有检测到实际可翻译文本块后才宣告正文就绪，并将 Quiz 的等待窗口延长到 30 秒；普通题目链接仍在 6 秒内快速分类，不会拖慢整门课程。任务完成或取消后可选择“仅重试失败项”，旧版曾误判为跳过的 Quiz 也会纳入补跑，已完成讲义继续复用本地缓存。

`1.0.2` 修复章节目录扫描的状态机竞态：20 秒未收到 iframe 消息时自动重新加载一次，再等待 30 秒才进入诊断；章节身份改用稳定的数字 ID 匹配，不再依赖完整路径字符串。“继续”现在能从诊断状态真正恢复并重新扫描当前章节。

`1.0.3` 修复课程首页无法导出的问题：整库导出改由顶层内容脚本执行，不再错误依赖文章 iframe。弹窗会等待生成结果并显示文章数量、Markdown/HTML 文件名或明确错误；两个下载错开触发，降低浏览器合并或拦截同时下载的概率。

`1.0.4` 重建课程导出导航：合并旧版本按章节 ID 保存的多个目录碎片，以课程 slug、章节标题和文章 ID 生成唯一目录，正文严格按目录顺序分章排列。每章增加章节导航页，每篇提供上一篇、下一篇、本章目录和总目录双向跳转；正文内部重复锚点按文章隔离，避免跨篇串跳。

`1.0.5` 修复任务结束后计时继续增长的问题，完成、取消和阻塞状态固定显示 `finishedAt - startedAt`。当前任务日志扩展到最近 200 条；终态任务自动生成不含课程正文的历史快照，保存在 `chrome.storage.local`，最多保留 20 个任务且不超过 30 天，可在进度页选择查看。

`1.1.0` 引入多课程工作区：段落译文缓存继续跨课程共享，但文章归档使用“课程 slug + 文章 ID”隔离；目录、统计、历史和 Markdown/HTML 导出均限定为当前课程。一次只运行一个批任务，避免多个课程争抢 Ollama；切换课程时弹窗显示独立归档覆盖率。条目按 LeetCode 元数据区分 `Article`、`Problem` 和 `Quiz`，不再把 System Design 讲义误判为练习题。视频课程的文字会进入个人讲义，视频本身不会复制。

多课程归档启用 `unlimitedStorage`，避免两门大型课程的逐篇归档与译文缓存触发 Chrome 普通本地配额。弹窗显示扩展本地数据总占用。图片、视频和 iframe 以原始在线资源链接保存在 HTML/Markdown；链接仍受来源站点权限和有效期约束。HTML/Markdown/PDF 均只用于个人学习，不应重新发布课程内容。

## 边界

- 只在 `https://leetcode.com/explore/*` 和你当前已经登录、能正常观看的页面上工作。
- 不获取 Cookie、不调用 LeetCode 私有 API、不绕过登录或付费校验。
- 不批量爬取课程、不导出原文，也不用于分享或重新发布受版权保护的内容。
- 本地缓存只保存每个文本块的哈希和译文，用于避免重复推理；原文不会持久化到扩展存储。

## 1. 准备 Ollama

已安装 Ollama 时：

```bash
ollama pull qwen3:8b
ollama serve
```

在 macOS 上通过 Ollama 应用启动服务也可以。确认服务正常：

```bash
curl http://127.0.0.1:11434/api/tags
```

默认使用 `qwen3:8b`。8 GB 内存机器可考虑较小模型；16 GB 及以上通常能流畅运行 8B 量化模型。模型越大，术语一致性通常越好，但首屏等待时间也更长。

## 2. 安装扩展

1. 打开 `chrome://extensions`（Edge 使用 `edge://extensions`）。
2. 开启右上角“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择本目录 `tools/leetcode-local-translator`。
5. 固定扩展图标，打开任意 LeetCode Explore 课程文章。
6. 点击扩展图标，选择“双语对照”或“仅显示译文”，再点“翻译当前页面”。

### macOS：首次授权扩展访问 Ollama

Ollama 默认可能拒绝 `chrome-extension://...` 来源，并返回空的 `403`。打开扩展的“模型与服务设置”，页面会显示当前扩展的精确 Origin 和对应命令。复制到终端运行：

```bash
launchctl setenv OLLAMA_ORIGINS "chrome-extension://这里是设置页显示的扩展ID"
```

然后从 macOS 菜单栏彻底退出 Ollama，再重新打开 Ollama 应用。必须重启 Ollama 进程才能读取新环境变量。不要改用 `OLLAMA_ORIGINS="*"`；精确 Origin 权限更小。

首次翻译需要加载模型，可能比后续请求慢。之后同一文本会直接命中本地缓存。
如果扩展是在 LeetCode 页面打开之后才安装的，弹窗会自动把页面脚本补注入，无需手动刷新标签页。
翻译启动后，页面右下角会显示正文识别、当前批次、缓存命中数和完成状态。8B 模型首次加载以及第一批推理通常最慢。

翻译完成后，当前章节会自动进入扩展的本地归档。弹窗提供：

- **保存当前章节**：同时下载双语 Markdown 和独立 HTML；
- **导出已归档章节**：把所有你亲自打开并完成翻译的章节合并下载为 Markdown 和 HTML。

批量归档不会在后台爬取课程目录，也不会绕过 LeetCode 的访问控制；阅读时正常打开各章节并翻译即可自动积累。合并 HTML 可直接在浏览器打开，通过“打印 → 存储为 PDF”生成 PDF。建议仅作个人学习使用，不分享或重新发布付费课程内容。

缓存、归档和任务状态都保存在浏览器扩展自己的 `chrome.storage.local` 中。暂停或取消不会清除它们：已返回批次的段落译文和已完成文章归档会保留，重新运行时可复用；只有取消瞬间仍在推理、尚未返回的当前批次不会写入缓存。卸载 Ollama 的驻留模型只释放内存，不影响浏览器里的缓存与归档。

`0.3.0` 起会在送入模型前保护行内 `code` 和 KaTeX/MathML 公式，译后恢复原 DOM，避免公式被拆成多行或重复翻译。升级后旧缓存不会复用，因为缓存协议版本已更新。

`0.4.0` 会读取当前已授权页面中呈现的 `.chapter-item` 和 `.item-list-group` 导航元数据，自动建立“课程 → 章节 → 条目”框架。首次访问即可保存所有可见章节骨架；每次打开一个章节，会将其展开条目合并到本地目录。合并导出按该目录排序，并用 `✓/[已归档]` 与 `○/[未归档]` 标记状态。目录只用于组织本地个人归档，不会据此后台抓取未打开正文。

`0.5.0` 提供显式启动的课程批处理：先以 2 秒间隔扫描章节目录，再以默认 8 秒间隔逐条打开当前账号可访问的课程条目、翻译并归档。独立进度页显示阶段、总进度、当前条目、倒计时、成功/跳过/失败和日志，支持暂停、继续、取消；失败条目最多重试 2 次。任务状态持久化在扩展本地存储中。

`0.6.0` 从当前页面自动识别课程根地址，因此适用于采用相同 Explore 页面结构的其他可阅读 LeetCode 课程。弹窗可直接选择 Ollama 已安装模型、页面间隔以及“测试 2 条 / 测试 5 条 / 完整课程”。建议先用 `qwen3:8b` 测试 2 条，确认正文、公式、归档和导出后再选择完整课程。打印讲义加入 A4 页边距、封面、目录、分页控制、中文字体、代码与双语块样式，可直接用浏览器打印为 PDF。

`0.7.0` 修复顶层 frame 空目录和章节首页选择器不匹配的问题。验证任务收集到前 2 篇后立即停止扫描；完整任务才扫描全部章节。任何章节 15 秒内无法识别目录时进入诊断状态，不会再以 `0/0` 冒充完成。弹窗改为“当前页面 / 课程任务 / 归档”三个区域，并将验证与完整课程拆为两个独立操作。

`0.8.0` 在进度页同步显示两类不同状态：扩展当前是否正在发送推理请求，以及 Ollama 当前有哪些模型驻留内存。暂停、取消和“仅中断当前推理”都会通过 `AbortController` 真正终止扩展发起的 fetch；关闭网页本身不再是取消手段。每个驻留模型可单独用 Ollama `keep_alive: 0` 安全卸载，释放统一内存。页面还显示上次推理是完成、失败还是取消。

标题提取会排除 `Report Issue`、`Previous` 和 `Next`，源地址也会去除内部 iframe 使用的 `?iframe=0`。

模型行为：

- `qwen3:8b`、`qwen3:14b` 等通用模型使用批量 JSON 协议，速度更高；
- `translategemma:12b` 等 `translategemma:*` 模型自动使用官方推荐的英→简中单段提示格式，质量优先、逐段处理，速度会慢一些。

## 3. 工作方式

LeetCode Explore 会把文章放在同源 iframe 中。扩展注入所有 frame，但只有检测到 `.article-inner .block-markdown` 的文章 frame 才会工作；外层导航页面及文章内嵌的视频、代码编辑器 frame 不会作为独立文章处理。它翻译标题、段落、列表、引用、表格单元格、折叠问答和选择题文本，并将代码及媒体链接作为不翻译的静态内容归档。

- `pre`、`code`（不翻译，但会原样归档）、输入框和操作按钮；
- Monaco/CodeMirror 编辑器；
- 页面导航、页头、页脚；
- 可编辑区域和不可见内容。

文本按约 5,500 字符、最多 12 项一批送入 Ollama。模型必须按带 ID 的 JSON 返回结果，扩展按 ID 写回对应 DOM 节点。LeetCode 使用 SPA 导航或懒加载内容时，路由轮询与 `MutationObserver` 会发现新增正文并继续翻译。

缓存键包含模型名、目标语言和正文 SHA-256，因此修改模型或目标语言后不会错误复用旧译文。

## 4. 设置

在扩展弹窗中进入“模型与服务设置”，可修改：

- Ollama 地址，默认 `http://127.0.0.1:11434`；
- 模型，默认 `qwen3:8b`；
- 目标语言，默认 `Simplified Chinese`；
- temperature，默认 `0.1`。

如果 Ollama 跑在另一台自己的设备上，建议通过 Tailscale/SSH 隧道访问，且只允许可信设备。不要把未鉴权的 `11434` 端口暴露到公网；如改变地址，还需在 `manifest.json` 的 `host_permissions` 中加入该地址并重新加载扩展。

## 5. 效率与质量建议

- 日常阅读用双语模式，可快速核对术语；熟悉章节后切到仅译文。
- 第一次进入章节后稍等页面完成渲染再点击翻译，减少碎片请求。
- 译文出现明显错误时保留原文核对。尤其是 `subarray`、`subsequence`、`in-place`、摊还复杂度等术语，不应只看中文。
- 若希望重新翻译同一模型的旧结果，在扩展管理页进入“检查视图 → Service worker”，执行 `chrome.storage.local.clear()`；这只清除译文缓存和扩展本地状态。

## 6. 故障排查

**“连接失败 / Failed to fetch”**

确认 Ollama 正在运行，并在弹窗点“测试 Ollama”。如果自定义了地址，检查 `host_permissions`。

**Ollama 403**

正文提取已经成功，但 Ollama 拒绝浏览器扩展来源。进入“模型与服务设置”，复制自动生成的 `launchctl setenv OLLAMA_ORIGINS ...` 命令运行，然后彻底退出并重新打开 Ollama。`0.2.1` 的“测试 Ollama”会同时测试真实翻译接口所需的 CORS 权限，不再只测试模型列表。

**模型不存在**

运行 `ollama list`，确保设置中的名称完全一致；否则运行 `ollama pull <模型名>`。

**模型返回 invalid translation payload**

小模型偶尔不遵循 JSON。重试一次，或换用 `qwen3:8b` 及更强模型。temperature 保持 0–0.2。

**页面没有内容被翻译**

确认 URL 位于 `/explore/` 下，并在升级至 `0.2.0` 后重新加载扩展、刷新 LeetCode 标签页一次。`0.2.0` 已适配 Explore 的同源文章 iframe 和 `.article-inner .block-markdown` 正文容器。若 LeetCode 将正文 DOM 结构整体改版，在 `content.js` 中调整 `isArticleFrame()`、`rootNode()` 和 `BLOCKS` 即可，无需改翻译服务。

**Receiving end does not exist**

这是旧版 `0.1.0` 在扩展安装前已打开页面时的注入问题。`0.1.1` 会自动检测并补注入。到 `chrome://extensions` 点击本扩展的“重新加载”以启用新版本和新增的 `scripting` 权限。

**Extension context invalidated**

这表示 Chrome 已重新加载或更新扩展，但当前标签页还运行着旧内容脚本。刷新该 LeetCode 标签页一次即可。`0.1.2` 增加了内容脚本版本探测和明确的页面内错误提示；正常使用期间不需要反复刷新。

**隐私验证**

断开网络但保留 Ollama 运行，已经加载完成的 LeetCode 页面仍可翻译。也可以用浏览器开发者工具 Network 面板确认扩展只请求 `127.0.0.1:11434`。

## 文件说明

- `manifest.json`：最小权限与 LeetCode Explore 注入范围。
- `content.js`：DOM 提取、SPA/动态内容监听、缓存和双语渲染。
- `background.js`：与 Ollama 通信及严格 JSON 翻译协议。
- `popup.*`：翻译、显示模式、连接测试。
- `options.*`：本地服务和模型设置。
- `styles.css`：页面内译文样式。
